# API Architecture Documentation

هذا الملف يشرح تنظيم وطريقة عمل الواجهات البرمجية (APIs) داخل النظام.

## المسارات المنجزة (Completed APIs)

### 1. `GET & POST /api/agents`
**الوظيفة:** إدارة وكلاء الذكاء الاصطناعي (Agents).
*   **GET**: تجلب جميع الوكلاء المحفوظين، مرتبين بالترتيب الزمني.
*   **POST**: لإنشاء وكيل جديد، يستقبل (الاسم، الوظيفة، مساحة العمل / systemPrompt).

### 2. `GET & POST /api/vault`
**الوظيفة:** إدارة الخزنة الآمنة للمفاتيح والمحافظة على خصوصية النظام.
*   **GET**: يجلب المفاتيح المحفوظة **(الأسماء فقط)**، مثل (API_KEY_GEMINI)، وبدون إرجاع القيمة المشفرة إطلاقاً حرصاً على الأمان العالي.
*   **POST**: يستلم القيمة المفتوحة من المستخدم، يقوم بعمل تشفير `AES-256-CBC` مستخدماً `ENCRYPTION_KEY` الموجود في ملف `.env`، ثم يحفظها.

## المسارات التي تتطلب البرمجة لاحقاً (Pending Implementation Routes)
*(هذه المسارات واجهاتها الأمامية جاهزة وتعمل، وتنتظر فقط البرمجة الفعلية للسيرفر)*

### 1. `POST /api/ingest`
**الوظيفة المطلوبة:** استلام النص من شاشة الكتابة (`/write`).
1.  أخذ النص، إرساله لمكتبة `ai-sdk` وتحويل النص إلى `Embeddings` (عمليات رياضية تحلل معنى الكلمات).
2.  حفظ الناتج الرياضي في `Pinecone`.
3.  حفظ النص الأصلي في MySQL جدول الـ `Node`.

### 2. `POST /api/search`
**الوظيفة المطلوبة:** البحث المختلط (Hybrid).
1.  المستخدم يكتب "كيف أقوم ببناء موقع؟".
2.  السيرفر يحول السؤال لـ Embedding هندسي.
3.  يتم البحث داخل Pinecone عن أقرب هندسة معمارية مشابهة لمعنى الجملة ليجلب الـ IDs.
4.  يتم استدعاء النصوص الأصلية από MySQL وإعادتها وعرضها في شاشة `/search`.
