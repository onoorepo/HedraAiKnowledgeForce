# مخطط وهندسة قاعدة البيانات (Database Schema Overview)

تعتمد منصة HAK على نظام هجين (Hybrid) لتخزين البيانات:
1. **MySQL (via Prisma)**: لتخزين العلاقات، النصوص الثقيلة، بيانات الوكلاء، والبيانات المشفرة.
2. **Pinecone (Vector DB)**: لتخزين النماذج المتجهة (Embeddings) وإجراء البحث الدلالي السريع.

## جداول MySQL الرئيسية (Prisma Models)

### 1. `Node` (عقدة المعرفة الأساسية)
تمثل أي قطعة معلومات في العقل الثاني (ملاحظة، مقال، كود، معلومة).
*   `id`: المعرف الفريد.
*   `title`: عنوان العقدة.
*   `content`: المحتوى الفعلي.
*   `pineconeId`: كود فريد لربط هذه العقدة بمكانها في Pinecone Vector.
*   `type`: نوع المعرفة (مستند، ملاحظة، كود).
*   `sourceId`: (اختياري) معرف المصدر الأصلي لو كانت مستوردة من منصة أخرى.

### 2. `NodeRelation` (روابط الـ Knowledge Graph)
لربط العقد مع بعضها البعض (مثلاً العقدة A تعتمد على العقدة B).
*   `sourceNodeId`: الشريك الأول.
*   `targetNodeId`: الشريك الثاني.
*   `relationType`: نوع العلاقة (مراجع، أب لـ، مشابه لـ).

### 3. `VaultSecret` (الخزنة المشفرة التامة)
لتخزين كلمات المرور و API Keys.
*   `keyName`: اسم المفتاح (GEMINI_API_KEY).
*   `encryptedVal`: القيمة المشفرة باستخدام `AES-256-CBC` والمكوّنة من `IV` والنص المشفر.

### 4. `Agent` (جدول جيش الوكلاء)
تخزين الوكلاء المصممين للقيام بمهام مخصصة.
*   `name`: اسم الوكيل.
*   `role`: التخصص.
*   `systemPrompt`: الأوامر الداخلية التي تتحكم في تفكيره وقراراته.

### 5. `Conversation` & `Message`
محاكاة لمحادثات كاملة مستوردة أو داخلية.
*   `Conversation`: السجل الرئيسي (يدعم فيس بوك، واتساب).
*   `Message`: الرسائل بداخل السجل، مع توقيتاتها وبيانات المرسل.

## آلية الربط المتجهي (Vector Binding - Pinecone)
عندما يتم حفظ `Node` في MySQL، يقوم السيرفر بأخذ حقل `content` وإرساله لـ AI ليتحول إلى أرقام متجهة (1536 بُعد أو 768 بُعد بحسب الموديل).
يتم رفع هذه الأرقام المتجهة إلى `Pinecone` مع حفظ المعرّف (ID).
عند البحث، نقوم بالبحث في `Pinecone` أولاً لاستخراج أفضل ID متطابق، ثم نقوم بجلب النص المقابل له من `MySQL` وعرضه للمستخدم بأجزاء من الثانية!
